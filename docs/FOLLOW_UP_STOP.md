# 15分後フォローの停止

担当者がGmailから案内を送った場合、社内の予約通知メールにある
「【社内用】手動でメールを送ったら、15分後メールを停止」を使います。

1. 通知の「停止・状況確認」リンクを開く。
2. Resendの `prosent` チームにログインし、対象の宛先・件名を確認する。
3. 右上の `…`（More actions）→ `Cancel schedule` を選ぶ。
4. 確認画面が出たら確定し、`Canceled` の表示を確認する。

通知には実際にResendへ渡した送信予定時刻を日本時間で表示します。
その時刻より前に停止操作を完了してください。送信済みのメールは取り消せません。
Resend自身の時刻表示が異なるタイムゾーンの場合は、通知内の日本時間を参照してください。

## 動作範囲

- 反映後に受け付けた、全体験のお客様向けフォローが対象です。
- リンクは案件ごとのResendメールIDを使い、他案件の予約には作用しません。
- リンクを開くだけでは停止しません。メールのリンクスキャンでも停止されません。
- 管理リンク・ID・停止手順は社内通知だけに入ります。顧客の受付返信やフォロー本文には入りません。
- スケジュール失敗時、取引先問い合わせ、予備配送ルートには停止リンクを出しません。
- 過去の通知にはリンクが追加されません。既存分はResendのEmailsから探してください。
- 停止はフォローの送信予約だけです。体験予約の取消や台帳のステータス変更ではありません。
- 予約時点の通知本文は、停止後も書き換わりません。最新の送信状態はResendで確認します。

## Gmail送信後の自動停止について

この変更は手動停止への導線です。Gmail送信の自動検知は実装・接続されていません。
現行の `kamehame-site` キーはSending accessのため、権限を広げず、既存の
Resendログインと管理画面を使います。新たな公開取消APIや認証情報は追加しません。

自動化する場合は別途、Gmail送信済みの監視、予約通知と返信の正確な対応付け、
Resend取消APIの権限確認が必要です。同じ宛先の別予約を止めないよう、
メールアドレスだけでは判定せず、通知ID・件名の体験と日付も照合します。
受付自動返信を人間の返信と判定しないこと、送信直前の競合・取消失敗を
記録することも必要です。現在の15分後送信の動作は継続します。

## 検証

`node --test tests/follow-up-notification.test.mjs` はResendをモックして、
フォーム受付→送信予約→社内通知のID・時刻の対応、顧客メールへの管理リンクの
非混入、送信予約失敗、取引先問い合わせを確認します。実際のメールは送りません。
