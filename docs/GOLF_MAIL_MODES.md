# ゴルフメール：手配料方式とパッケージ方式

2026-10-17。運用スイッチは `lib/golf-prices.ts` の `GOLF_MODE` のみ。
変更前の全コードは Git ブランチ `backup/golf-mail-before-arrangement-20261017`（コミット `008c688`）に保存。

## 現在の手配料方式

| タイミング | 内容・経路 |
|---|---|
| 問い合わせ直後 | Resendで受付メール。5言語のHTML＋テキスト。コースの予約はまだ未確定。 |
| 15分後 | Resendの予約送信。5言語で現地費用・送迎・アシスタントとの区分を説明。英語はエリア別の写真付き。決済リンクは付けない。 |
| コース・料金確認後 | 担当者が下記のコマンドで決済案内の下書きを作り、既存の「メール送信キュー」で確認・承認して送信。 |

- 手配料は税込15,000円×1〜4人。クラブ持参による手配料の値引きはしない。
- プレー代・カート・レンタル・昼食・コースキャディはゴルフ場へ直接支払い。
- 送迎は会社を紹介するのみで、お客様が直接予約・契約・支払い。現地の英語アシスタントは別見積もり。
- 料金版は `arrangement-2026-10-17`。旧パッケージの `2026-10-10` と区別。
- 手配料の取消料は7日前18時まで無料、以降3日前まで50%、2日前以降100%。天候によるコース閉鎖・手配不可は手配料を全額返金。球場の取消条件は別途、支払い前に提示。
- 旧Apps Script用のURL・TOKENが本番に残っていても、新規の手配料案件をその経路には送らない。関数の直接呼出しも拒否する。
- 受付と15分後メールは `RESEND_API_KEY` が必要。Resend失敗時の既存Cloudflare代替経路は運営通知のみで、お客様には送れない。運営側で確認する。

## 決済案内の作成

1. `docs/golf-arrangement-proposal.example.json` を `outputs/` 以下などGit管理外へコピーする。
2. 台帳の実在する案件ID、お客様情報、提案コース・ティータイム、現地費用明細、球場の取消条件、提案有効期限を入力する。
3. **人数から手配料専用リンクを自動選択する。** 2026-10-17にオーナーが指定した4本を `lib/golf-arrangement-payments.ts` に登録済み。東京・富士で共通。提案JSONに `payment` を入力する必要はない。以前のJSONに `payment` が残っている場合は、人数・金額・通貨・料金版・URLが登録値と完全一致するときだけ使用できる。別人数や旧パッケージのリンクは拒否する。

   | 人数 | 手配料（税込） | 登録リンクの末尾 |
   |---|---:|---|
   | 1名 | 15,000円 | `8x228rcQhejp8qP2sG3Je0l` |
   | 2名 | 30,000円 | `8x2bJ16rT2AHbD19V83Je0m` |
   | 3名 | 45,000円 | `7sYeVd3fHcbh22rc3g3Je0n` |
   | 4名 | 60,000円 | `3cI3cvcQh5MTgXlffs3Je0o` |

   人数分をまとめた一括料金。リンクの数量を人数分に増やさない。手配料の単価だけ変更し登録リンクの金額が追従していない場合も、生成を停止する。
4. 実行：`npm run golf:email -- outputs/proposal.json outputs/case-id-draft`
5. `email.html` と `email.txt` を確認する。`queue-draft.json` は「メール送信キュー」の列名に対応。実際の行に内容を登録し、既存の承認手順で送信する。コマンドはメール送信・シート書込・自動承認をしない。保存先に同名ファイルがあれば上書きしない。

英語の決済案内を実装。その他の言語は翻訳を確認した個別案内とし、このジェネレーターでは生成を拒否する。受付・15分後メールは5言語対応。

コース提案なし、期限切れ、異なる日程、登録済みリンクと異なる金額・通貨・料金版・URLの場合は生成しない。Stripe APIの自動照合は行わない。実際のStripe設定が後から変われば検出できないため、送信時にも確認する。提案の期限表示はStripeリンク自体を失効させない。4本は人数別の共通リンクなので、1件の提案期限切れだけで無効化すると同人数の他案件にも影響する。期限後の支払いは個別確認し、案件ごとの自動失効が必要な場合は専用Checkout Session等への変更が必要。

15分以内に個別返信した場合、通常のResend予約メールはGmail返信だけでは自動停止しない。運営受付メール内のResend管理リンクから取消す。詳細は `FOLLOW_UP_STOP.md`。

## 旧内容の保護と切戻し

- 旧決済本文は `lib/golf-package-email.ts` の `packagePaymentTemplate()` にそのまま移動。従来の写真・決済ボタン・クラブ持参割引・キャンセル条件を保持。
- 受付・フォローの旧文面は `lib/mail-copy.ts` に保持。新文面は別ファイルで分離。
- 法的表示の旧ゴルフ条項も保持。手配料方式のときだけ、メールと同じ支払い区分・返金条件を表示。
- 過去に送信したメール、既存の下書き・承認・送信待ち、Stripeリンク、台帳は移行・上書きしない。再送しない。

以前のパッケージ運用に戻す場合：

```sh
npm run golf:mode -- package
node --test tests/golf-automation.test.mjs tests/follow-up-notification.test.mjs
npm run build
git add lib/golf-prices.ts
git commit -m "Restore golf package mode"
# 通常のレビュー・main反映を行うとGitHub Actionsでデプロイされる
```

これはサイト料金・申込画面・受付／フォロー本文・決済テンプレート・料金版・ゴルフ特則を一緒に戻す。パッケージのApps Script自動化は従来どおりURL・TOKEN・GAS送信許可・承認済みリンクなどの条件が揃う場合のみ動く。新たに有効化はしない。

手配料方式へ戻すときは `npm run golf:mode -- arrangement`。いずれもソースの変更だけでは本番は変わらず、デプロイが必要。

変更全体を外したい場合は、この実装のコミットを通常の `git revert` で戻す。共有mainを `reset --hard` やforce pushで巻き戻さない。復元用ブランチへの切替だけでは本番は変わらない。

## 外部設定との境界

GitHubへの反映はWorkerの更新。`docs/payment-automation.gs` の変更は、外部Apps Scriptへ自動反映されない。追加した料金版の防御を使う場合はそのプロジェクトにも更新する。ただし新規手配料案件を遮断する主防御はWorker側にあり、GAS更新なしでも動く。

既存のGASキューは新規の受付経路と独立している。過去案件を停止する場合は台帳側の個別停止を使用し、本文を新方式へ置換しない。新方式からパッケージへ戻すときも、新方式で受け付けた案件の約束を変更しない。

確認用テスト：`node --test tests/golf-arrangement-email.test.mjs tests/golf-automation.test.mjs tests/follow-up-notification.test.mjs tests/mail-queue.test.mjs`。
