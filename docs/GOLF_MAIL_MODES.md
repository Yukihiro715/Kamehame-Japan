### 料金と返金

- 手配料は1組の金額で、1名目15,000円＋2名目以降1名5,000円（税込。2名20,000円、3名25,000円、4名30,000円。2026-10-24 改定。10-23 までは1名15,000円×人数）。このうち調査・条件に合う提案が5,000円（1組あたり。オーナー承認 2026-10-24）、残りが予約・調整。クラブ持参でこの手配料は減額しない。
- 条件に合う具体的提案を送る前（調査着手前を含む）：全額返金。
- 合意した必須条件に合う具体的提案を送った後、予約確定＋書面通知の前：5,000円（1組）を頂戴し、残額を返金（1名なら10,000円、2名なら15,000円、4名なら25,000円）。
- 顧客承認済みのコース・時刻・費用・取消条件で予約を確定し、書面の確定通知を送った後：お客様都合の手配料返金なし。空き確認だけではこの段階にしない。
- 必須条件を満たせない、当社不備、天候によるゴルフ場閉鎖：当社手配料全額返金または顧客同意の代替案。
- ゴルフ場取消料は別。現地払いでも取消料が発生しうる。予約前に金額・期限・条件を提示して承認を得る。
- 名称を「調査料」にすれば無条件で保有できるわけではない。実作業・提案・同意の記録を残し、適用法令に反する額は請求しない。新しい定額の運用実績に合わせて費用根拠を確認する。
- 既存顧客の個別合意（全額返金の約束を含む）は維持。旧規定で進行中の案件を新規定へ自動移行しない。

価格版は `arrangement-2026-10-24`（単価・Stripeリンクの識別子。旧 `arrangement-2026-10-17` は1名15,000円×人数）。返金規定版は別に `staged-2026-10-24`（旧 `staged-2026-10-19` は提案後に1名5,000円を保有）。
新規の通知に表示規定版を記録するが、フォーム送信だけでは有料調査・返金条件への合意とは扱わない。

### 2名以上の個別提案

`lib/golf-individual-offer.ts` は担当者用の下書き専用。サイトや自動受付・フォローには読み込まない。
原則「手配のみ」と「プレミアム車両によるホテル往復送迎・英語アシスタント付き」の2案。
送迎不要と明確に希望された場合はその意向を尊重する。

旧料金や既存顧客向けキャンペーンを新規案件へ自動適用しない。見積もり未確認なら、興味の有無とホテル・乗車場所を聞く。
金額を記載する場合は `privateQuote` に総額、含まれるもの、除外・現地払い、契約先、決済先、取消条件と `verifiedForThisRequest: true` が必須。
手配料リンクで送迎付きプランを回収しない。プラン変更時は既払額の扱いを事前に明示し二重徴収を避ける。

**個別メールも旅行業法の適用除外ではない。** 実際の契約・代理・集金の役割を、提携先と所管行政に確認する。
旅行サービス手配業登録と、旅行者に直接販売する旅行業登録は別制度。相手が適切な契約主体かを案件で確認する。
本変更で提携先の登録、契約成立、旅行契約の代理権を認定するものではない。

### 個別メール下書きの作成

1. `docs/golf-arrangement-proposal.example.json` を `outputs/` 等のGit管理外へコピーする。実顧客データはコミットしない。
2. 台帳案件ID・顧客、希望日、希望時刻、必須条件、希望条件、レンタル、総予算と範囲、案内有効期限を入力する。
   予算未回答を上限なしとしない。明示的に上限なしとの回答を得た場合のみ `totalJpy:null, noCeilingConfirmed:true`。
3. `policyVersion: "staged-2026-10-24"` と適用資格を確認する。
   新規かつ旧条件の約束がない場合 `eligibility:"new-enquiry-no-prior-terms"`。
   既存顧客が着手前に条件変更へ書面同意した場合のみ `customer-agreed-change-before-work` と `changedTermsAgreement` の証拠参照を入力する。
   既存JSONはこの確認なしに新規定メールへ変換できない。既存規定の案内は個別作成する。
4. `npm run golf:email -- outputs/proposal.json outputs/case-id-draft`
5. HTML・テキスト・`queue-draft.json` を確認し、既存送信キューに下書きとして登録、所定の承認後に送信。
   CLIは送信・シート書込・自動承認をしない。以前の下書きは上書きしない。

英語の担当者向け下書きを実装。その他の言語は確認済み翻訳で個別対応。自動受付とサイトは5言語。
支払いボタンは条件・返金説明の後。生成時点の説明だけで合意済みとみなさず、実際の返信を確認する。

### 記録と既存案件

案件ごとに規定版・必須条件・予算範囲・顧客同意のメールID/日時・入金確認・調査開始・適合提案の内容と送信日時・予約承認・ゴルフ場の予約確定証跡・確定通知の送信日時を残す。
費用保有の根拠は実際の作業・達成段階に基づく。台帳や送信済みメールの旧約束を上書きしない。
このリリースは自動返金、予約実行、既存キュー更新、一括送信を実装しない。

## 旧内容の保護と切戻し

- 旧決済本文は `lib/golf-package-email.ts` の `packagePaymentTemplate()` にそのまま移動。従来の写真・決済ボタン・クラブ持参割引・キャンセル条件を保持。
- 受付・フォローの旧文面は `lib/mail-copy.ts` に保持。新文面は別ファイルで分離。
- 法的表示の旧ゴルフ条項も保持。手配料方式のときだけ、メールと同じ支払い区分・返金条件を表示。
- 過去に送信したメール、既存の下書き・承認・送信待ち、Stripeリンク、台帳は移行・上書きしない。再送しない。

以前のパッケージ運用に戻す場合：

```sh
npm run golf:mode -- package
node --test tests/golf-automation.test.mjs tests/follow-up-notification.test.mjs
npm run build
git add lib/golf-prices.ts
git commit -m "Restore golf package mode"
# 通常のレビュー・main反映を行うとGitHub Actionsでデプロイされる
```

これはサイト料金・申込画面・受付／フォロー本文・決済テンプレート・料金版・ゴルフ特則を一緒に戻す。パッケージのApps Script自動化は従来どおりURL・TOKEN・GAS送信許可・承認済みリンクなどの条件が揃う場合のみ動く。新たに有効化はしない。

手配料方式へ戻すときは `npm run golf:mode -- arrangement`。いずれもソースの変更だけでは本番は変わらず、デプロイが必要。

変更全体を外したい場合は、この実装のコミットを通常の `git revert` で戻す。共有mainを `reset --hard` やforce pushで巻き戻さない。復元用ブランチへの切替だけでは本番は変わらない。

## 外部設定との境界

GitHubへの反映はWorkerの更新。`docs/payment-automation.gs` の変更は、外部Apps Scriptへ自動反映されない。追加した料金版の防御を使う場合はそのプロジェクトにも更新する。ただし新規手配料案件を遮断する主防御はWorker側にあり、GAS更新なしでも動く。

既存のGASキューは新規の受付経路と独立している。過去案件を停止する場合は台帳側の個別停止を使用し、本文を新方式へ置換しない。新方式からパッケージへ戻すときも、新方式で受け付けた案件の約束を変更しない。

確認用テスト：`node --test tests/golf-arrangement-email.test.mjs tests/golf-automation.test.mjs tests/follow-up-notification.test.mjs tests/mail-queue.test.mjs`。
