# 体験事業者向け募集LP

- LP: https://kamehame-japan.com/partners-lp/
- 相談後に案内する詳細登録フォーム: https://kamehame-japan.com/partners-lp/register/
- 既存の `/partner/` 管理画面と `/partners/` ページは維持。

## 受付・審査の流れ

相談・詳細登録のどちらも `/api/supplier` で検証し、既存の `RESEND_API_KEY` と `CONTACT_TO`（任意で `ARCHIVE_TO`）を使用して担当者へメール通知する。設定がない場合・送信サービスが失敗した場合は、完了を表示せず再送とメール連絡先を案内する。送信時には受付番号、同意と登録時の条件バージョンを含める。Resendの冪等キーで短時間の再送重複を抑制する。データの受付記録は通知先メールボックスで保管する。新しい公開DBや自動掲載は作成しない。

1. 担当者が「掲載のご相談」通知へ返信する。
2. 掲載を希望する事業者に上記登録URLを案内する（通知本文にもURLを記載）。相談直後にはお礼・受付番号・担当者からの連絡予定を記した自動返信を送る。登録リンクは自動返信に入れず、担当者から案内する。
3. 「体験情報の登録・審査待ち」の通知で体験情報・卸価格を確認する。
4. 審査、販売・支払条件の合意、原稿翻訳・確認を経て、既存の掲載運用で公開する。

登録フォームは案内メールから開く公開URLで、認証付きではない。検索エンジン向けにnoindexを設定し、LPやサイトマップには登録フォームへのリンクを掲載しない。提出した連絡先や卸価格をページへ公開しない。任意の下書き保存はブラウザ内に限る。

## 検証

`node --test tests/supplier-enquiry.test.mjs` で入力・同意・価格・URL検証、担当者への通知と相談者へのお礼メール、再送キー、送信失敗、Origin制限、スパム対策をモックで確認する。実メールを送るテストは実施しない。

## 写真・マーク

承認済みLPプレビューから画像とサービスマークを移植。ホテルの写真は説明用の生成イメージで、実在の提携先の紹介ではない。各ブランドは販促接点の説明であり提携表明ではない。


## 相談フォーム・自動返信（2026-11-15更新）

相談フォームには任意の電話番号、必須の体験名・サービス名（仮称可）を設ける。モバイルの入力欄は16px以上にして、iOSのフォーカス時ズームを避ける。利用者のピンチ拡大は制限しない。

相談の担当者通知とお礼メールはResendの同一バッチで送信し、2件分の受付IDを確認してから完了を返す。再送時は同じ冪等キーを使用する。自動返信はHTMLとテキストを用意し、返信先をhello@kamehame-japan.comに設定。未加工の相談本文・外部リンクや登録フォームURLは自動返信に含めない。詳細登録フォームの受付は従来どおり担当者通知。

## 複数料金・料金表の受付

詳細登録の料金ステップは「フォームに入力」「料金表を提出」から選ぶ。フォームでは最大8プラン、それぞれ1名一律、人数帯別の1名単価（最大12帯）、1組・貸切、基本料金＋超過人数分、個別見積もりに対応する。金額は税込の整数円。人数帯別は予約人数に応じて全員の単価が変わり、重複する人数帯を拒否する。未登録の人数帯は要確認として通知し、自動で補間しない。追加人数料金は含有人数を超えた人数にのみ適用する。含有人数0も指定できる。

一般向けの定価がないプラン、お支払額を相談したいプランはそれぞれ明示的に選択する。一般価格がある場合の25％引きは押した場合のみ入力する補助で、入力済み金額を自動変更しない。子ども・季節・オプション・最低請求条件は任意の追加欄で申告する。これらの自由記述条件は担当者の確認が必要で、自動計算・自動公開はしない。

料金表提出ではPDF／Excel（xlsx、xls）／PNG／JPEG／WebPを最大3件、1件5MiBまで添付できる。掲載用写真と料金表の添付合計は8MiBまで。共有URLとの併用も可能。一般価格のみの資料ではご希望のお支払額の説明か相談希望の選択を必須とする。添付はファイル名、拡張子、サイズ、Base64と基本的なファイル署名を検証し、固定の担当者通知先へResendの単通送信で転送する。公開ストレージへの保存や公開URLの生成はしない。ファイル署名の検証はウイルススキャンを意味しない。共有URLの内容はサーバーから取得しない。

入力プラン・追加条件は下書き保存できる。添付バイナリは下書きに保存せず、復元時に再選択が必要なファイル名を表示する。旧下書きの一般価格・卸価格は復元するが、料金方式と人数は再確認を求める。登録の送信には現在の条件確認と写真1枚以上が必要。

新しい料金構造はクライアントとAPIで共通検証し、選択していない方式の入力は通知に含めない。担当者通知にはプラン名、人数、1名／1組／追加1名の単位、条件、添付名を記載する。利用者へのレスポンスには受付番号のみを返し、価格・添付情報を露出しない。検証は `node --test --test-concurrency=1 tests/supplier-enquiry.test.mjs tests/supplier-pricing.test.mjs tests/supplier-pages.test.mjs`。実際のメール配信を伴わず、送信サービスのリクエストをモックで確認する。

## 写真・集合場所・送信制限

掲載用のPNG／JPEG／WebPを1枚直接アップロードする。追加写真は最大2枚のアップロードか共有URLを選択できる。添付は各5MiB以下、料金資料と合わせて8MiB以下。ファイルと署名をサーバーでも確認し、担当者通知メールのみに添付する。下書きには保存しないため、復元後に写真の再選択が必要。写真のSNS・広告への使用許可は任意で記録し、未許可なら掲載ページ用途に限定する。SNSアカウントURLと集合場所のGoogle マップURLは任意。地図と集合の詳細は担当者確認・予約確定後の共有用で、公開掲載データへ自動転記しない。

APIは送信元Originを先に確認し、同一サイトからのリクエストのみIP制限に加算する。制限は本文の読込より先に適用する。異なるOriginの拒否リクエストが、共有IPの正規送信枠を消費しないことを回帰テストで確認する。
