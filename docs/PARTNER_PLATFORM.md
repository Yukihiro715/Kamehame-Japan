# 提携パートナープラットフォーム（Step 2: 一般化と精算）

設計は `docs/PARTNER_PLATFORM_STAGE1.md`。ここでは Step 2 で入ったものと運用手順をまとめる。ホテル紹介の段階 2・3（`docs/HOTEL_REFERRAL.md`）はそのまま土台。

## 2a. 提携パートナーへの一般化（移行 0008）

- 契約先（`partner_legal_entities`）に **種別**（ホテル / 旅行代理店 / ガイド / その他）、**形態**（法人 / 個人）、連絡先メール。
- 拠点（`hotels` テーブル、画面では「拠点」）に **拠点種別**（施設 / 支店・拠点 / ガイド本人 / その他）と **使える機能** `features_json`: `refer`（リンク紹介）、`cases`（予約取り次ぎ、Step 3）、`settlement`（精算閲覧・確認）、`members`（メンバー管理、Step 3）。種別と機能は独立。
- 役割に `partner_agent`（取り次ぎ担当）と `partner_manager`（拠点管理者）を追加。`cases` が有効な拠点でだけ招待できる。既存の閲覧担当者・請求担当者はそのまま。
- 機能の判定はサーバー（`lib/portal/partner.ts` の `requireFeature`）。`refer` を切った拠点は、リンク・QR の新規発行ができず、`/r/<token>` は通常ページへ案内するだけで紹介セッションを作らない（既存セッションの予約は影響なし）。
- 運営 → 提携パートナー: 契約先の登録で「拠点も同時に作る」を選ぶと、個人ガイドや支店のない代理店を 1 回で登録できる（契約先と同名の拠点と精算設定ができる）。拠点の詳細で種別と機能を切り替える。
- 既存データの移行はなし（列追加と既定値のみ）。公開 ID、照合番号、リンクのトークンは変わらない。

## 2b. 精算（段階 4、移行 0009）

### 流れ

1. **締め**（運営 → 精算、経理または管理者）: 四半期が終わったら対象四半期（例 `2026-Q3`）を入力して実行。精算先ごとに下書きの「お支払い通知書」ができる。対象は、実施確認済みで保留のない確定紹介料のうち通知書に未収載のもの（遅れて確定した前四半期分も含む）と、発行済み通知書に載った予約の訂正明細（`commission_adjustments`）。何度実行しても下書きを作り直すだけで、発行済みには触れない。
2. **発行**: 通知書の詳細で「発行する」。請求担当者（いなければ契約先の連絡先メール）に通知メール。異議申立て期限 = 発行日 + 精算設定の `dispute_days`（既定 14 日）。
3. **確認 / 異議**（パートナー → 精算）: 請求担当者が「内容を確認しました」か「異議を申し立てる」（通知書全体または明細ごと、理由必須）。期限を過ぎて無反応なら 5 分おきの cron が自動で確認済みにする。期限後の異議は受け付けない。
4. **異議への回答**（運営）: 「原案どおり」なら発行済みに戻る。「認容」なら予約の明細・実施記録・料率を訂正してから通知書を **無効** にし、同じ四半期を締め直すと **訂正版（版 2）** ができる。無効にした版も履歴として読める。
5. **支払バッチ**（運営 → 支払）: 支払日を指定して作成。その日までに支払予定で振込額のある通知書（発行済み・確認済み）を精算先ごとに 1 振込にまとめる。「振込リスト CSV」を銀行のツールに取り込み、結果（支払済み / 失敗 / 保留）と参照番号を登録する。支払済みで通知書は「支払済み」、パートナーに完了メール。失敗は次のバッチに再び載る。銀行への自動送金はしない。

### 金額の決まり（`lib/portal/settlement.ts`）

- 紹介料は予約ごとに四捨五入済みの台帳値。消費税は通知書の税抜合計に対して 1 回（T09）。
- 繰越: 直前の通知書（発行済み以降）の「次回繰越」を「前期からの繰越」に入れる。お支払い対象額 = 税込合計 + 繰越。
- 最低お支払額（精算設定 `min_payout_jpy`、既定 3,000 円）は **税込の対象額で判定**。未満なら全額を次回へ繰越し、振込額 0。
- 振込手数料（`bank_fee_jpy`、`fee_borne_by = 'hotel'` のとき）は振込額からだけ差し引く（T11/T12）。
- 返金で対象額がマイナスになったら、そのまま次回へ繰越して相殺する（T28）。
- 支払日 = 四半期末の翌月末。土日なら前営業日（祝日は未考慮。必要なら運営がバッチの支払日で調整）。

### 帳票

- 通知書は画面（`/hotel/settlement/<id>/`、`/ops/settlement/<id>/`）の「印刷 / PDF保存」でブラウザから PDF にする（D-2 案 A）。明細 CSV も同じ数字。
- 記載: 宛先（契約先名・所在地・登録番号）、発行者、期間、通知書番号、税抜・消費税・税込・繰越・対象額・次回繰越・手数料・振込額・振込予定日、明細、注記（算出方法、繰越、異議期限、支払通知書方式）。税務上の記載事項の追加は経理確認のうえ `components/portal/statement-sheet.tsx` を直す。

### テスト

`tests/settlement.test.mjs`（締め・繰越・最低額・手数料・再実行・発行・確認・異議・訂正版・支払バッチ・CSV・自動確認）、`tests/partner-platform.test.mjs`（種別と機能の独立、個人ガイド、紹介スイッチ）。既存の `portal-api`、`referral-*` は変更なしで通る。

### 本番に必要な設定

- 追加のシークレットはない。移行 0008・0009 はデプロイで自動適用。
- 精算先ごとの条件（最低額、手数料負担と金額、異議日数）は当面 SQL で更新する（`settlement_profiles`）。画面からの編集は Step 3 以降。
- 口座情報は `bank_details_masked`（表示用）のみ運用。暗号化保存（`bank_details_enc`）は未実装のため、振込リスト CSV はマスク表示で、実際の口座は銀行側の登録を使う。
