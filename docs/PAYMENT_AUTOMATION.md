# ゴルフの決済案内・配信計測

コードと台帳の準備段階。公開だけでは新しい自動化は有効になりません。
`GOLF_AUTOMATION_URL` と `GOLF_AUTOMATION_TOKEN` の両方を設定した後に受け付けたゴルフ案件のみ対象です。
設定前の既存15分フォロー、および他の体験は従来経路のままです。

## 分岐と停止

- おすすめコース、2〜4名、東京・埼玉・千葉の送迎、開催日が日本時間の今日から5日以上先、追加オプションなし、特別な備考なし、確認済みの料金・リンクあり → 受付メール送信後10分を目安に支払い案内。15分メールなし。
- レンタルは人数分の `required:right` / `required:left` / `own` が確認できる場合のみ自動。`own`（クラブ不要）1名につき5,000円引き。クラブ不要人数・割引後総額まで一致する承認済みリンクがある場合に自動案内します。リンク未登録・レンタル未定・特殊仕様は手動対応です。
- キャディ「あり」は専用の承認済みリンク・総額・キャディ追加料金が必要。「相談したい」は手動。
- 備考は空欄または「なし」「Thank you」等の定型だけ自動。それ以外は運営が判断します。英語以外の支払い案内は、テンプレート確認まで手動です。
- その他は理由付きで運営に通知。15分以内に対応がなければ既存の挨拶メールを送信。
- 1分ごとのApps Scriptトリガーで処理するため数分の遅延はあり得ます。予定から1時間を超えた案件は保留して通知します。
- 送信直前にGmailを再確認。担当者の送信、お客様からの返信、手動停止、配達エラー、入金済みなら停止。Gmail照合エラーは送信せず要確認。
- 件名に案件IDを付けて照合。別件との対応が曖昧な場合も保留して通知します。Gmailの検索反映と送信直前の競合を完全に排除することはできません。手動対応の前に台帳の「手動停止」を「停止」にするのが確実です。
- Gmailで閲覧しただけでは停止しません。送信したメールだけが対応扱いです。

## 決済リンクマスター

`Stripe決済リンク管理` の4行目が見出しです。既存19列に、キャディ／自動送信可／料金版／キャディ追加料金（税込）／自動送信確認メモを追加。

自動対象には以下がすべて必要です。

1. 区分=標準プラン、体験カテゴリ=プライベートゴルフ、エリア・人数・キャディ・クラブ不要人数が一致。
2. 料金版=2026-10-10、自動送信可=可、Stripeリンク状態=有効、通貨=JPY。
3. `book.stripe.com` または `buy.stripe.com` のURLと実際の `plink_` ID。
4. 総額=サイトの基本料金＋キャディ追加料金－クラブ不要人数×5,000円。キャディなしは追加料金0。キャディありも追加料金を明示入力。
5. Stripe管理画面で有効状態・金額・通貨・数量固定・割引や追加商品の設定を確認済みであること。

シートの承認値を使います。Stripeの現在設定を直接読むAPIキーは追加していません。Stripe側で変更したときは先に「不可」に戻し、照合後に承認し直してください。自動対象が複数ある場合も送信しません。送信時にもマスターを再読込します。
`クラブ不要人数` 列を末尾に追加し、0〜人数の整数を入力します。従来の標準リンク行は空欄を0として扱うため、既存運用を維持できます。割引リンク行は必ず人数を明示。区分は「標準プラン」のまま、人数別・クラブ不要人数別・キャディ有無別に行を分けます。例えば東京2名で2名ともクラブ不要なら総額240,000円・クラブ不要人数2です。人数分のレンタル希望が不明な場合は価格から推定しません。

初期データは全行「不可」。キャディあり6プランは料金・URL・リンクIDが未入力です。

## 本番設定の順序

1. 返信に使うGmailアカウントで、台帳用の**独立したApps Scriptプロジェクト**を作り、`payment-automation.gs` を配置。既存台帳スクリプトを上書きしないでください。
2. スクリプトのタイムゾーンを `Asia/Tokyo` にする。スクリプトプロパティへ次を設定（ソースやシートには秘密値を保存しない）。
   - `SPREADSHEET_ID`: 対象台帳ID
   - `AUTOMATION_TOKEN`: 十分に長いランダムな共有秘密値
   - `RESEND_API_KEY`: 既存ドメインの送信キー
   - `TEAM_EMAIL`: 運営の受信先
   - `STAFF_EMAILS`: 返信担当の送信アドレス・エイリアス、カンマ区切り
   - `LIVE_SEND_ENABLED`: 最初は `false`
3. 「自分として実行」のWebアプリとしてデプロイ。Workerから呼べるアクセス設定とし、すべての処理で共有秘密値を検証します。Apps Script実行者が台帳とGmailの両方にアクセスできる必要があります。
4. `installGolfQueue()` を実行してSheets/Gmail/外部リクエストの権限を認可し、1分トリガーを作成。実行エラー通知を担当者が受信できる状態にする。
5. Cloudflare Workerに `RESEND_WEBHOOK_SECRET` と `STRIPE_WEBHOOK_SECRET` をSecretで設定。GASと同じ共有値を `GOLF_AUTOMATION_TOKEN` に設定。URLを設定する前に以下の接続・試験を完了。
6. Resendで `/api/webhooks/resend` を登録。sent, delivered, delivery_delayed, bounced, failed, suppressed, complained, opened, clicked を購読。署名秘密値をWorkerと一致させる。ドメインのOpen/Click trackingを有効化し、SPF/DKIM/DMARC・送信ドメインの状態を確認。HTMLメールの画像読込とリンクリダイレクトを計測します。秘密値は通常のAPIキーとは別です。
7. Stripeで `/api/webhooks/stripe` を登録。checkout.session.completed / async_payment_succeeded / async_payment_failed を購読。**本番**の署名秘密値を設定。URLは `https://kamehame-japan.com` に続けます。
8. 別のテスト台帳・テスト宛先で下記を確認。本番客へテスト送信しない。テストモード決済は本番入金として扱いません。
9. 既にResendに予約済みの15分メールを一覧確認し、手動対応済み分を取消。新キューへ過去案件を再投入しない。
10. 承認する決済リンクを照合。GAS `LIVE_SEND_ENABLED=true`、Worker `GOLF_AUTOMATION_URL` を `/exec` URLに設定し、新規分を切替。台帳「メール配信集計」D2の未稼働表示を稼働開始日時へ更新。

Gmailを別のアカウントから送る場合、その送信済みメールをスクリプト実行アカウントが読めなければ検知できません。開始前に実際の返信アカウント・エイリアスで停止試験してください。

## 確認項目

ローカル: `npm run build` と `node --test tests/golf-automation.test.mjs tests/follow-up-notification.test.mjs tests/rendered-html.test.mjs`。

今回のローカル結果: ビルド成功、新規10テスト成功、全体29件中27件成功。残る2件（開発用previewメタタグ、未使用scrollbarユーティリティ）とTypeScriptの既存Worker型2件は、変更前の `710fbbf` を別チェックアウトでビルドして同じ失敗を再現済みです。GAS/Gmail/Resend/Stripeの本番接続試験は未実施です。

本番接続前の管理下テスト:

- 受付が1回だけ保存・送信され、同じリクエストIDの再試行で重複しない。
- 10分経過で決済案内のみ、手動案件は15分後に挨拶のみ。
- 14分時点で担当者が返信 → 挨拶なし。顧客返信・手動停止も同様。
- Gmail権限を外す、決済リンクを不可にする → 自動送信を保留。
- 配達・開封・決済リンククリック（署名URLを除外）イベントが正しい案件へ記録される。
- 入金イベントの重複は1回、金額不一致・別リンク・テストモードは入金扱いにしない。
- トリガーを止めて再開した際、1時間超の滞留分を勝手に送らない。

送信途中に不明なエラーになった場合は自動再送しません。Resendの実際の送信状態を確認して手動対応します。保存済みの送信途中状態を再開する場合だけ、同一本文・同一冪等キーを使用。Resendの冪等キーの保持期間（24時間）より十分短い1時間で打切ります。

## 台帳と計測の読み方

プロモーションコードは許可できます。署名検証済みStripeイベントについて、割引前小計が案内した税込固定パッケージ額と一致し、割引額が非負整数、実入金額＝小計－割引額、追加税・送料が0であることを照合します。通貨・リンクID・本番モード・paidも必須です。全額割引（0円）や内訳欠落は手動照合とします。

`メール自動化管理` のS列は実入金額、V列は割引前金額、W列は割引額、X列は使用コード／IDです。Webhookに展開済みコード文字列があれば記録し、IDのみならIDを記録します。どちらもない場合は「コード未取得」と記録し、Stripe決済IDから確認します。既存U列の内部データは移動しません。更新時は先にV:X列と見出しを追加し、GASとWorkerを更新してから自動送信を有効化してください。

- `メール自動化管理`: 案件ごとの送信状態・停止・配達・開封・クリック・入金。内部データ列は非表示で、編集しないでください。
- `メール配信ログ`: 署名検証後のイベントを重複排除して記録。
- `メール配信集計`: 支払い案内メールの案件数を分母にした各率。未計測を0%の実績と混同しないよう、未稼働を明示。
- 配達は受信側メールサーバーの受理であり、迷惑メールフォルダーを含む受信箱の配置は判別できません。開封とクリックは画像ブロック・プライバシー機能・リンクスキャンの影響を受ける参考値。
- 未開封だけでSMSを送らない。配達失敗・苦情等は停止して運営へ通知。WhatsApp/SMSの送信自体は今回自動化しません。
- **Gmailから直接手動送信したメールの開封・クリック・配達は、この仕組みでは測れません。** 人が作成・承認する個別メールは、台帳の「メール送信キュー」から同じResend経路で送って計測します（`MAIL_TRACKING.md`。ゴルフ自動化とは別のスイッチで動きます）。Gmail返信の検知は、送信抑止にのみ使用します。
- 過去の案内・以前のStripeリンクで支払われた分は既存の手動照合を継続。新規リンクには個人情報を含まない案件IDを付与し、金額・通貨・リンクID・本番モードを照合します。
- メール配信失敗通知も届かない場合があるため、Apps Scriptの実行失敗通知・`LAST_QUEUE_RUN`・台帳の最終エラーを運営が確認してください。

## 停止・切戻し

個別停止は「メール自動化管理」の手動停止欄。全体停止はGASの `LIVE_SEND_ENABLED=false` とトリガー停止。WorkerのURLを外すだけでは既存キューは停止しません。URLを外すと**新規分が旧15分フローに戻る**ため、全体停止を済ませてから切戻します。

参考: [Resend webhook events](https://resend.com/docs/webhooks/event-types)、[Svix verification](https://docs.svix.com/receiving/verifying-payloads/how-manual)、[Stripe reference IDs](https://docs.stripe.com/payment-links/url-parameters)、[Apps Script triggers](https://developers.google.com/apps-script/guides/triggers/installable)。

## 2026-10-16 写真付きHTMLの組み込み

- 東京（千葉夷隅・ブリストルヒル）、富士（冠雪富士山の富士小山・朝霧）の承認済み写真を同じドメインに配置。640pxのメール用テーブル、上部と取消条件後の決済ボタンを使用。
- 金額・人数単価・リンク・キャディ条件は送信直前の承認済みマスターからtext/HTML両方に反映。HTMLの全文とテキストを送信前に保存し、途中再開で変更しない。
- レンタルシューズ込みに修正。クラブ不要は1名5,000円引きで、条件に一致する承認済みリンクがあれば自動案内。個別仕様・不明なレンタル情報は手動見積もりへ。1週間以内追加1万円引きは個別提案のため全件へ自動適用しない。
- Gmailに加え、個別メールキューの承認済み／送信中／送信済み／結果要確認・エラーを照合。同じ顧客への手動対応があれば自動メールを保留。送信直前にも再照合するが、Gmail検索反映と送信の瞬間の競合は完全には排除できない。
- 新しい支払い案内は `photo-2026-10-16` 版のHTMLがない場合送信しない。既存ジョブを再投入しない。
